Question 3.5:
What is the canonical transcript accession for Ensembl Gene id ﻿ENSG00000266960?
sql (with a few extra results to better understand data):
SELECT 
  g.id_gene,
  g.ENSEMBL_GENE_ID,
  t.id_transcript,
  t.IS_CANONICAL,
  t.accession
FROM gene g
JOIN transcript t USING (id_gene)
WHERE g.ENSEMBL_GENE_ID = 'ENSG00000266960';

ans: ENST00000586416

Question 3.7:
Imagine that we have a table called “some_gene” with only a subset of the gene data. If I want to join the gene table with this table but display all the genes in the result, what kind of join would you do?
Ans - I would use a left (or right) join if I want to display all the genes 

(for testing) 
create table some_gene as (select * from gene where ID_BIOTYPE=23);

select gene.id_gene as g1, some_gene.id_gene as g2 from 
gene left join some_gene on gene.id_gene = some_gene.id_gene;

**This will join both tables and display all the genes ids in the result - whene there is no match it will just show null

Question 3.8:
Imagine that the gene and transcript tables are getting very big and that joining the two tables get slower and slower. What would you do to improve performances?
Ans: The first thing I would try to add are indexes, for faster access:
CREATE INDEX transcript_id_idx ON transcript(id_gene);
CREATE INDEX gene_id_idx ON gene(id_gene);

This should make the join much faster, event for big tables.
If the tables become even bigger it can get more complicated and there are not always easy solutions.
One option I could do is keep lighter versions of the tables (e.g. just Id and Accession) and then add an option to join a table with more info (e.g. gene features)
But this requires a change in architecture so depends on context. 
From experience in Ensembl if both tables are indexed a join should work fairly fast for big databases.

Question 3.9:
If you want to avoid duplicates in a table, what kind of index would you create?
Ans:When creating the table I would add the "Unique" constraint - e.g.  "ID int NOT NULL UNIQUE"
If the table already exists, I would use alter , e.g. "ALTER TABLE Persons ADD UNIQUE (ID)";

Question 3.10:
If you want to make sure that all the id_gene ids in the transcript table exists in the gene table, what kind of index would you create?
I would add a foreign key constraint - this would mean that you won't be able to add a new transcript without a gene id match with the table gene
For example:
ALTER TABLE transcript
ADD CONSTRAINT fk_transcript_gene
FOREIGN KEY (id_gene)
REFERENCES gene(id_gene);
